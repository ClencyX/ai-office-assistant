# AI辅助办公应用

一期是一个中文本地办公任务管理平台，适合个人记录任务、跟踪交付和管理周期工作。前端使用原生 HTML、CSS 和 JavaScript，服务端使用 Node.js 内置 HTTP 与 SQLite，应用无需安装第三方依赖。

## 已有功能

- 工作总览、任务台账、列表与看板，支持搜索、筛选和分页查看全部任务。
- 新建、编辑、改派、开始处理、完成和重新打开任务；所有状态均可编辑。
- 按文本、表格、演示文稿、PDF、图片或不限设置提交形式，完成任务前必须上传符合格式的交付材料。
- 已提交材料下载、任务操作历史、删除确认、回收站与恢复。
- 每周、每月、每季度、每年固定任务，支持 CSV 批量导入。
- 临期、到期和逾期站内提醒，任务台账导出与 SQLite 数据备份。
- 可选的 Server酱个人微信推送，每天汇总待处理任务，支持测试发送和失败后手动重试。
- 简洁中文页面，适配桌面与窄屏。

当前版本默认供本机管理员单人使用，业务页面仅监听本机地址。负责人用于任务归属和提醒筛选，目前没有独立用户登录、多人权限或 AI 文档生成。无需模型账号；可选微信推送需要自行配置 Server酱 SendKey。GitHub 上的代码协作与应用内多人共同办公是两件独立的事。

## 获取代码

在仓库页面点击 **Code → Download ZIP** 下载后解压，或复制仓库的 HTTPS 地址进行克隆：

```sh
git clone https://github.com/yinghuili625/ai-office-assistant.git
cd ai-office-assistant
```

下面所有命令都在包含 `package.json` 的项目目录执行。

## 本地运行

安装 [Node.js 24 或以上版本](https://nodejs.org/)，然后运行：

```sh
node --version
npm start
```

无需执行 `npm install`。启动后打开 [中文工作台](http://127.0.0.1:3080)，在命令行按 `Ctrl+C` 停止服务。本地模式使用内置定时器，每分钟检查固定任务和提醒；电脑关机、休眠或服务停止时不会执行检查。

首次创建数据库时会写入演示任务和固定任务规则。示例只初始化一次，后续启动继续使用已有数据。如希望从空白数据库开始，在第一次启动前设置环境变量 `SEED_DEMO=0`。例如 PowerShell：

```powershell
$env:SEED_DEMO = '0'
npm start
```

直接运行 `npm start` 时，环境变量由当前终端提供，不会自动读取 `.env`。可选变量包括 `PORT`（默认 `3080`）、`DATA_DIR`（默认项目内的 `data`）、`SEED_DEMO`（默认启用演示数据）和 `SERVERCHAN_SENDKEY`（可选微信推送密钥）。

### Windows 启动脚本

双击 [启动平台.cmd](启动平台.cmd) 可自动选择可用的 Docker 或本地 Node.js，启动后打开页面；使用结束时双击 [停止平台.cmd](停止平台.cmd)。脚本根据所在目录定位代码和数据，可在不同电脑上的任意项目目录使用。

明确选择本地模式：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Mode Local
```

脚本首次运行会自动生成本地 `.env`，其中包含随机调度与工作流密钥。脚本模式如需空白初始化，可先仅生成配置：

```powershell
. .\scripts\common.ps1
Initialize-Platform
```

然后把 `.env` 中的 `SEED_DEMO` 改为 `0`，再启动平台。这只影响数据库的首次初始化，不会清除已有任务。

### Docker 与定时工作流

在 Windows 安装并启动 Docker Desktop，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Mode Docker
```

脚本准备密钥并启动应用与 n8n 定时工作流。业务页面仍为 `http://127.0.0.1:3080`，仅供维护的 n8n 编辑器为 `http://127.0.0.1:5680`。首次拉取镜像需要网络。

已有 `.env` 后，也可以使用 Docker Compose：

```sh
docker compose up -d --build --wait
docker compose logs --tail 100 application n8n
docker compose down
```

不要同时使用本地与 Docker 两种方式操作同一份数据库。修改代码后，Docker 模式需重新构建应用镜像才能生效。

## 完成任务与提交材料

任务的“提交形式”决定支持的文件：

| 提交形式 | 支持的扩展名 |
| --- | --- |
| 文本 | `.txt`、`.md`、`.doc`、`.docx`、`.rtf` |
| 表格 | `.csv`、`.xls`、`.xlsx` |
| 演示文稿 | `.ppt`、`.pptx` |
| PDF | `.pdf` |
| 图片 | `.png`、`.jpg`、`.jpeg`、`.webp` |
| 不限 | 以上全部格式 |

点击“标记完成”后，上传 1—5 个文件，单个不超过 10 MiB，总计不超过 25 MiB，并确认已按交付要求核对内容。系统校验格式、大小和基础文件结构，业务内容由提交人确认。重新打开任务后，再次完成需要上传本次材料；历史材料保留。

## 个人微信推送

1. 登录 [Server酱](https://sct.ftqq.com/)，取得 Turbo 版 `SCT` 开头的 SendKey，在其控制台绑定本人的微信，并选择微信服务号通道。`sctp` 开头的 Server酱³ Key 用于独立 App，不适用于本功能。
2. 打开应用的 **提醒中心**，配置个人微信推送：填入 SendKey，选择负责人范围与北京时间发送时刻，保存并启用。负责人留空时汇总全部符合条件的任务，填写姓名时只匹配该负责人。
3. 可先发送测试消息，收到后再确认正式配置。测试使用固定虚构内容，也会消耗 Server酱服务额度。

默认关闭推送，默认发送时刻为北京时间 `09:00`。服务运行期间，每天到时后有未完成的临期、到期或逾期任务时，汇总推送一次；站内提醒是否已读不影响汇总。成功记录跨重启去重，失败不自动重试，可在提醒中心手动重试。网络超时可能无法判断服务端是否受理，重试前先查看微信以免重复。所有发送操作限频，约每 60 秒可调用一次；Server酱自身另有通道、额度和频次限制，以其控制台为准。

正式消息仅发送任务标题、负责人和截止日期等摘要，最多 50 条、约 8 KB；超出时提示回到本机查看。任务正文和交付文件不会发送。API 返回成功仅表示 Server酱已受理，不能确认微信最终送达；真实投递需使用自己的 SendKey 和已绑定的通道验收。

页面配置的密钥保存在本机 `data/serverchan.json`，接口不返回密钥。也可使用环境变量 `SERVERCHAN_SENDKEY`，它优先于本机配置；页面无法覆盖或删除环境变量中的密钥。Windows 启动脚本会读取 `.env` 中的该变量，Docker Compose 会将其传入应用；直接 `npm start` 则需要先在当前终端设置环境变量。推荐使用页面配置，勿将 SendKey 放进源码或分享截图。

此功能是一套本机配置对应一个 Server酱接收端，负责人筛选仅控制摘要范围，不代表给每名负责人分别投递。

## 数据与备份

业务数据库和交付材料保存在 `data/office.sqlite`，微信发送记录保存在其中的 `serverchan_records` 表，均纳入 SQLite 业务备份。可在平台设置下载完整业务备份，也可使用 [备份数据.cmd](备份数据.cmd)。`backups/` 存放本地备份，`data/n8n/` 存放工作流运行数据。

微信设置和 SendKey 单独保存在原子写入的 `data/serverchan.json`，不包含在业务备份中；迁移时应另行安全保留该文件或重新配置，环境变量中的密钥则随本机 `.env` 或终端环境另行保存。恢复较旧的业务备份可能丢失当天发送记录，重新启用推送前先核对微信消息，避免重复发送。

代码仓库不应包含 `.env`、`data/`、`backups/`、个人任务、上传文件或运行日志。下载或克隆代码会创建独立的本地数据，不会获得仓库维护者的业务数据。迁移自己的数据时应单独备份，停止服务后再恢复；请勿通过 Git 分享数据库或密钥。

## 开发与验证

```sh
npm test
```

自动化测试使用隔离数据库，覆盖任务流程、周期调度、提醒、导入、材料校验、备份、回收站、Server酱配置与发送行为以及 HTTP 接口。测试替代外部网络调用，不会向真实微信发送消息。

| 目录或文件 | 用途 |
| --- | --- |
| `public/` | 中文页面、样式与交互 |
| `server.mjs` | HTTP 服务与接口路由 |
| `lib/` | SQLite 业务逻辑、文件校验和 CSV 处理 |
| `test/` | 自动化测试 |
| `scripts/` | 启动、停止、备份和工作流初始化 |
| `workflows/` | n8n 工作流配置 |
| `compose.yaml`、`Dockerfile` | 容器运行配置 |
